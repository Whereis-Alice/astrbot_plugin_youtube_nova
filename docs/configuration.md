# 配置说明

## 解析与触发

“YouTube 输出模式”控制文本和富媒体是否发送。自动解析开启时，消息中出现受支持的 YouTube 链接即可触发；也可以只保留“媒体解析”等关键词，或开启引用消息触发。

同一链接和同一用户的频率限制默认关闭。需要限制时设置最大次数和统计窗口，记录保存在插件自己的运行时目录。

## 视频体积、压缩与群文件

插件把三件事分开处理：

- “视频大小上限”是管理员允许下载的硬上限，默认 1000 MiB。
- “可发送视频体积上限”只决定能否作为普通视频消息发送，默认 48 MiB。
- “超限视频投递方式”默认“上传为文件（群聊/私聊）”：原视频超过普通发送上限后直接文件投递，跳过压缩。也可明确选择仅发送信息与封面。

“上传为文件（群聊/私聊）”在 QQ 群聊使用 `upload_group_file`，在 QQ 私聊使用 `upload_private_file`，收件人始终来自当前会话。NapCat、SnowLuma、LLOneBot / LLBot 均支持这些 OneBot v11 动作，通过 AstrBot 的 aiocqhttp 适配器接入。旧“上传为群文件”配置仍可使用。协议端不支持、权限不足或明确拒绝时保留已有卡片/摘要，并提示原因和原链接。

**旧版本升级**：面板已保存的“仅发送信息与封面”不会被自动改写。要启用新的原文件投递，将该项切换为“上传为文件（群聊/私聊）”。超过普通上限后，即使旧压缩策略设为“始终压缩”，也会优先上传原文件。169.7 MiB 的视频在 48 MiB 普通上限和 1000 MiB 下载硬上限下直接发送为文件；超过 1000 MiB 则仍会停止下载。

“文件上传来源”（`download.group_file_source_mode`）支持 `auto`、`local` 和 `http`：

- `auto`：配置了 `callback_api_base` 时使用 AstrBot 文件服务的短期 HTTP URL；未配置时使用本地路径。插件“文件中转”的回调地址优先于 AstrBot 全局配置，无需开启普通媒体文件中转。
- `local`：协议端必须能读取 AstrBot 使用的绝对文件路径。Docker 部署须把共享目录挂载到双方相同路径。
- `http`：强制文件服务传输，回调地址须能从协议端访问。适合不同容器或不同主机；地址未配置或注册失败会提示原因。

HTTP 模式使用带有效期的文件 token，不把大视频整体编码为 Base64；上传回执不确定时保留源文件供协议端继续读取。`callback_api_base` 应指向 AstrBot 服务地址，不能填仅在 AstrBot 容器内可达的 `localhost`。

旧协议端若返回空 `data`，aiocqhttp 无法区分完成与异步受理，插件会保守提示“未确认”，文件仍可能已经发送；请先查看会话，勿立即重复解析。已核对的三端当前源码完成回执均含 `file_id`。

文件上传超时控制本次调用的完整回执等待（默认 600 秒），不会修改其他消息的超时。回执超时或连接中断只表示结果未确认，上传端可能继续工作；插件不会自动重复上传，请先查看当前会话。未确认或取消等待后，源文件会再保留至少 10 分钟（配置超时更长时跟随该值），并写入持久化过期标记，避免立即清理打断上传。

视频压缩默认关闭。处理顺序为“下载 -> 超限且支持文件则直接上传原视频 -> 其余视频按压缩策略处理 -> 普通消息或封面”。压缩可以关闭、始终执行，或只在超过自定义阈值时执行；明确选择封面回退或会话不支持文件时仍可使用压缩。目标体积、编码器、预设、最大分辨率、最大帧率、固定视频/音频码率、CRF、重试次数、超时和附加 ffmpeg 参数均可配置。阈值或目标体积填 0 时优先跟随普通发送上限；固定码率或 CRF 模式只编码一轮，产物仍需满足目标体积，否则保留原文件并进入后续投递判断。

启用压缩或文件投递后，yt-dlp 会在管理员硬上限内优先取得高质量源文件，再交给后处理；两者都关闭时才直接把普通发送上限作为选流预算。48 MiB 是针对 LLOneBot/QQ Highway 53 MiB 实测拒收边界预留波动后的保守值，并非 QQ 固定协议上限。

## 代理

先填写代理地址，再开启“YouTube 解析与下载使用代理”。YouTube 的 googlevideo 直链可能绑定取链时的出口，因此解析和下载必须走同一代理。支持 `http://`、`https://` 和运行环境可用的 SOCKS 代理形式。

代理地址属于部署配置，不应写入仓库。

## 卡片与文本

卡片提供一套 YouTube 仿站皮肤和极光、报章、测控、展陈、夜曲五套通用皮肤，并独立控制布局、深浅色、水印、原链接和热评。“跟随平台”在本插件中等同于 YouTube 皮肤；旧配置里的 B 站或 X 皮肤值会自动迁移到 YouTube。卡片模式决定卡片与文本同条发送、分开发送或仅发送卡片。

“仅卡片”仍会保留必要的失败或媒体跳过提示，避免视频未发送却没有任何说明。

## Cookie

Cookie 接受 Netscape `cookies.txt`、扩展导出的 JSON 数组，以及 `a=1; b=2` 请求头格式。运行时轮换状态写在插件数据目录，不读取旧插件的状态文件。

Cookie 是账号凭据，只应填入 AstrBot 面板。不要放进配置示例、日志、Issue 或 GitHub 提交。

## 消息负载与本机诊断（v1.5.0）

`trigger.max_links_per_message` 默认 3，范围 1–20。按提取顺序处理前 N 个唯一链接；超出部分在当前会话提示后跳过，不占解析频率配额。普通消息、引用解析与归档共用此限制。需要更多链接时可拆成多条消息或调高配置。

AstrBot 管理员可发送 `/yt_status` 或 `/油管状态` 查看 yt-dlp、EJS、JS 运行时、FFmpeg、ffprobe、初始化时的缓存可用性、Cookie 来源、代理开关和体积上限。命令不访问 YouTube、不启动浏览器、不刷新 Cookie，也不显示 Cookie、代理地址或本机路径。依赖探测使用缓存，安装依赖后请重载插件再检查；报告中的“已配置”不代表登录态有效。
